=====================================================
 使い方
=====================================================

■ 学生（受験する人）

  1. https://tfuruhashi.github.io/n5/ を開く
  2. 学校のコードを入れる（例：TEST01）
  3. 名前・国籍・生年月日を入れる
  4. 10問に答える
  5. 結果が自動で学校に送られる

  ※ ログインは不要。コードだけで受験できる。


■ 学校（管理する人）

  1. https://tfuruhashi.github.io/n5/admin.html を開く
  2. メールアドレスとパスワードでログイン
     （Supabase の Authentication で作ったアカウント）
  3. 受験者の一覧が出る
  4. 「記録書」を押すと、入管提出用の記録書が別タブで開く
  5. 印刷ボタンから PDF で保存できる

  画面上部に「学生に渡すコード」が表示される。これを学生に伝える。


=====================================================
 データの見え方
=====================================================

  A校の職員は A校の学生の結果しか見えない。
  B校の結果は、URLを知っていても取得できない。

  これは Supabase の RLS（行レベルセキュリティ）で制御している。
  ログインしたアカウントの所属機関を staff テーブルで調べ、
  その機関のデータだけを返す仕組み。


=====================================================
 学校を追加するとき（今は手作業）
=====================================================

  ※ 学校が自分で登録できる画面は、まだ作っていない。
     当面は以下の手順で追加する。

  1. SQL Editor で機関を作る

     insert into institutions (name, code, address)
     values ('○○日本語学校', 'ABC01', '東京都○○区')
     returning id;

     → 表示された id を控える

  2. Authentication → Users → Add user で職員アカウントを作る
     Auto Confirm User をオンにする
     → User UID を控える

  3. SQL Editor で紐づける

     insert into staff (user_id, institution_id, name, role)
     values ('控えたUser UID', '控えたid', '担当者名', 'admin');

  4. 学校に「コード（ABC01）」と「ログイン情報」を伝える


=====================================================
 注意
=====================================================

  ・config.js に書いてあるキーは公開前提のもの。
    アクセス制御は RLS で行っている。
  ・service_role キーは絶対に config.js に書かないこと。
  ・問題は JLPT 公式問題ではない。自作の評価ツールである。
    記録書にもその旨が印字される。
  ・問題の中身は笈川先生に監修していただくべき。
